# 需求提案：`.skillhub` 仓库展示分类（切片二）

## 背景

切片一（`skill-install-mode-20260916-01`）已实现共享安装能力：真实文件落盘到 `~/.skillhub/skills/<slug>/`，各 agent 目录下创建指向它的软链接。

但当前「本地技能」页的扫描逻辑存在两个盲区，导致用户无法看到共享仓库的内容：

### 1. 扫描逻辑跳过 `.` 开头的目录

`local_skills.rs:121` 显式跳过所有以 `.` 开头的条目：

```rust
if name.starts_with('.') {
    continue;
}
```

这使得 `~/.skillhub/skills/` 作为扫描目标时，其子目录全部被过滤。

### 2. 分类维度只有 agent，没有仓库

当前扫描遍历 `AGENT_PROFILES`（5 个 agent），没有 `.skillhub` 仓库这一维度。

**后果**：
- 用户无法确认「技能是否已在仓库中」
- 无法看到一个共享技能被哪些 agent 链接引用
- 无法理解切片一产生的实际磁盘布局

## 目标

### G1. `.skillhub` 作为展示分类，与 agent 平级

- 在「本地技能」页的分类维度中加入 `.skillhub` 仓库
- 与 `claude-code`、`codex`、`opencode` 等**平级展示**
- 点击 `.skillhub` 分类后，列出仓库中存在的所有技能

### G2. 展示引用关系

- 每个仓库技能卡片上，显示它被哪些 agent 链接
- 例如：`weather` 技能在 `.skillhub` 中，被 `claude-code` 和 `codex` 同时链接
- 链接数用徽章展示（如 `🔗 2`）

### G3. 支持从仓库分类卸载

- 仓库分类下的技能可以卸载
- 卸载语义：删除该技能在仓库中的真实目录 + 所有指向它的链接
- **破坏性操作需二次确认**（明确告知会影响哪些 agent）

## 非目标

本切片**不做**以下内容，留待后续独立 change：

- **不做**孤儿技能清理（无任何 agent 链接的技能如何清理）
- **不做**批量迁移（不提供「把现有复制型技能转换为共享型」的一键操作）
- **不做**`.skillhub` 作为安装目标（不能「只存进仓库而不链到任何 agent」）
- **不做**线上版本对比 / 更新·替换（切片三）
- **不做**仓库分类的安装入口（只能查看和卸载，不能安装新技能到仓库）

## 已澄清的决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | `.skillhub` 分类语义 | **只作展示分类**，不可选为安装目标 |
| D2 | 引用关系展示 | 卡片上显示「被 N 个 agent 引用」+ 具体 agent 列表 |
| D3 | 卸载范围 | 仓库分类下卸载 = 删除真实目录 + 所有链接（需二次确认） |
| D4 | 扫描入口 | 新增 `repo_root()` 作为第六个扫描根，与 5 个 agent 并列 |
| D5 | 分类顺序 | `.skillhub` 排在最前（它是共享仓库，语义上优先） |

## 利益相关方

- **桌面端用户**：需要看到共享仓库内容，理解技能分布
- **多 agent 用户**：主要受益者，能看到一个技能被哪些 agent 共享
- **单向技能用户**：只装到一个 agent 的用户不受影响

## 验收标准

1. 本地技能页出现 `.skillhub` 分类，与 agent 分类平级
2. `.skillhub` 分类排在最前（顺序：`.skillhub` → `所有` → 各 agent）
3. 点击 `.skillhub` 分类后，列出仓库中所有技能（每个技能至少有一个 agent 链接）
4. 仓库技能卡片显示「被 N 个 agent 引用」徽章
5. 卡片上列出所有引用它的 agent 名称（如 `claude-code · codex`）
6. 仓库分类下支持卸载操作
7. 卸载前二次确认，明确告知会影响哪些 agent
8. 卸载后真实目录和所有链接同时删除
9. Web 端无 `.skillhub` 分类（Tauri only）
10. `.skillhub` 分类不可被选为安装目标（无安装按钮）

## 风险

### R1. 扫描性能

扫描 `~/.skillhub/skills/` 可能包含大量技能，需确认：
- 是否需要分页或虚拟滚动
- 是否需要增量扫描

**缓解**：先实现完整扫描，性能问题在验收时暴露再优化。

### R2. 卸载语义复杂

仓库分类下卸载 = 删除真实目录 + 所有链接，这与 agent 分类下「只删一个链接」语义不同。

**缓解**：
- 二次确认弹窗明确列出受影响的 agent
- 文案清晰区分两种卸载语义

### R3. 与切片三的边界

切片三（线上版本对比 / 更新·替换）也涉及仓库技能卡片。

**缓解**：本切片只做到「展示 + 卸载」，卡片上的「更新」按钮留待切片三。

## 范围切分

本 change 覆盖验收 **1-10**，对应 proposal 的 **G1-G3**。

与切片一的关系：
- 切片一：写入 `~/.skillhub/skills/`
- 切片二：读取并展示 `~/.skillhub/skills/`

与切片三的关系：
- 切片二：展示本地状态（已安装、引用关系）
- 切片三：对比线上版本（更新 / 替换操作）
