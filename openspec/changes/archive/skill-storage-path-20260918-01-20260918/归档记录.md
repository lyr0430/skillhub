## 需求摘要

（来自 `proposal.md`）

设置弹窗「Skill 配置」页当前只有「技能安装方式」一个配置项，其下方「注意」区块用 `bg-muted/50` 框式画法，视觉上像另一个配置项而非说明文字——本需求顺带修掉。同时共享安装把技能真实文件固定存放在代码常量 `~/.skillhub/skills`（`repo_root()`），路径不可迁移，且无入口查看技能仓库实际位置。

目标：
- **G1** 设置页新增「技能存储路径」配置项，与「技能安装方式」视觉分离；仅 Tauri 桌面端。
- **G2** 选择新目录：先二次确认 → 目录选择 → 整库移动 + 更新软链接。
- **G3** 支持恢复默认路径（同样二次确认）。

非目标：不做 copy 型已安装技能迁移、不做孤儿清理、不做 Web 端/CLI 端设置、不做按 agent 分别设定路径、不做批量搬移拷贝型技能。

## 技术方案摘要

（来自 `design.md`）

- 配置持久化：新增 `installer/storage_path.rs`，存储于 `dirs::config_dir()/skillhub/desktop-config.json`（JSON 键 `skillStoragePath`）。刻意不写入 `~/.skillhub`——该目录有三层语义（共享仓库根 `skills/`、CLI 工作区 `namespace-sync.json`、技能内 `metadata.json`），且桌面端只写 `skills/` 子目录。写回合并式（保留未知字段）。
- `repo_root()` 改造：由常量改为 `configured_repo_root().unwrap_or_else(default_repo_root)`；新增 `default_repo_root()`。所有消费方（共享安装、attach 源根、`.skillhub` 扫描、仓库卸载）都经 `repo_root()`，改一处全链路生效。
- 迁移命令：核心纯函数 `migrate_repo_root(from, to, agent_roots)`，预检中止（from 为目录；to 绝对且 != from；to 不在任何 agent root 内；to 不存在或为空，非空→冲突）、**rename 前**枚举软链接、整库 `fs::rename`（跨设备 `EXDEV` 报「仅支持同盘迁移」）、rename 后逐个重写链接（失败入 warning 不中断）。
- 命令：`get_skill_storage_path` / `set_skill_storage_path` / `reset_skill_storage_path`（`spawn_blocking`；rename 成功才写配置）。
- 前端：`settings-dialog.tsx` 新增存储路径分区（只读 Input + `FolderOpen` 按钮 + 二次确认 AlertDialog + 恢复默认按钮），`tauri-installer.ts` 新增 3 个命令封装，i18n 三语言。
- 权限：`capabilities/default.json` 补 `dialog:allow-open`。

## 评审结论

（详见 `评审记录.md`）

**有条件通过**（详见评审记录）。评审发现 2 处警告（W1、W2），均已在归档前修复，修复提交 `9074d551`：

| 级别 | 问题 | 处理 |
|---|---|---|
| W1（中） | 配置路径失效后用户无法恢复：外接盘卸载 / 目录被删后，`from.is_dir()` 预检失败，set/reset 双双失败，用户被锁死 | 已修复：新增 `validate_migration_destination`（目标校验不依赖源存在）+ `empty_migration`；set 在源缺失时仅校验并记录覆盖值，reset 在源缺失时直接清覆盖值回默认 |
| W2（中） | 仓库内 symlink 条目的 agent 链接被误删：`create_link` 拒绝 symlink 源，重写循环先删后建会把仍指向外部真实目标的可用链接删掉并重建失败 | 已修复：重写前判断 `to/<slug>` 是否为 symlink，是则跳过（其目标未随 rename 移动，链接仍有效） |
