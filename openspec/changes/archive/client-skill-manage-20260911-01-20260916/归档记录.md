## 需求摘要

（来自 `proposal.md`）

网页端「安装到 agent」当前只是把安装命令复制到剪贴板，用户需自行打开目标 agent 粘贴执行 —— 步骤繁琐、无反馈、「部署到本地」这一核心价值未被网页端承接。本变更将其升级为「点击 → 弹窗选目标 → 直接安装到本地」，并探索两条路径（优先网页端直接写文件系统，备选 Tauri 封装桌面应用）。

**验收标准 1–6**：按钮不再只复制命令、弹窗列出各 agent 与默认全局位置、成功后明确反馈、**确定并说明实现路径**、安装状态可反馈、至少一个自动化测试。

## 技术方案摘要

（来自 `design.md`）

- **选定 Tauri v2 而非网页端直写**（满足 AC4 的路径说明）：浏览器沙箱无法解析 `~/.claude/skills`、无法枚举本地 agent；File System Access API 要求每次手动挑目录、仅 Chrome/Edge、不支持 `~` —— 无法做到「点选 agent 一键安装」。
- **Tauri 壳 + 现有 React 前端**：一套前端代码两用；无 Tauri 时回退为原有复制命令行为，网页端零回归。
- **安装引擎用 Rust 原生**，不要求用户预装 Node/npm。
- **agent 目录映射对齐 `cli/src/agents/profiles/`**，避免桌面端与 CLI 两处漂移；核心先实现 claude-code / codex / opencode / openclaw + generic。
- 无数据库变更、无后端 API 变更（复用现有 zip 下载接口）；MVP 仅支持 PUBLIC 技能匿名安装。

### 已修复（按用户确认的范围：仅 HIGH 及以上）

1. **footer 被整段注释** —— `1c66bd8a` 把整个 `<footer>` 注释掉，与本变更主题无关，是误提交；`/`、`/privacy`、`/terms` 等所有公开页面因此失去 Privacy / Terms / License / GitHub / 版权入口，而 privacy/terms 的路由仍在（纯回归）。且上游此后删除了 `FOOTER_LINK_CLASS_NAME` 与 `BrandMark` 的 import，**无法靠反注释恢复**。已按上游版本恢复；恢复后该文件与 `upstream/main` **仅差本变更有意添加的两处 `isTauri` 导航项**，后续合上游几乎零冲突。
2. **弹窗注入硬编码中文 `sr-only` 取消按钮** —— Radix 打开时会把焦点落到该 `Cancel` ref 上，键盘用户焦点停在不可见控件；en/ru 用户被朗读中文「取消」。已移除（两个调用方的取消都是普通 `<Button>`，全仓无别的 `AlertDialogPrimitive.Cancel`）。
3. **`reqwest` 系统代理被连带关闭** —— `cargo tree` 确认 `system-configuration` 未解析；企业代理环境下安装下载失败且无提示。已加 `system-proxy` feature（`hyper-util/client-proxy-system`，全平台覆盖）。
4. **release 下启动失败完全静默** —— `main.rs` 设置了 `windows_subsystem = "windows"`，`.expect()` 的 panic 无处可见，用户双击后无窗口、无提示、无日志；且 `main` 返回 `()` 使退出码恒为 0。已改为写日志文件并以非零码退出。
5. **错误通道回显远端可控字符串** —— 见下方「对评审结论的纠正」。
6. 顺带：`withGlobalTauri` 由 `true` 改 `false`（全仓无人读 `window.__TAURI__`，属死配置）。

### 对评审结论的一处纠正

Rust 评审称「`registry` 带 userinfo 时凭据会进入 `network_error` 的消息」。**实测不成立**：reqwest 0.12.28 渲染 URL 时会剥掉 `user:password@`，实测原始 `Display` 为 `error sending request for url (http://127.0.0.1:1/nope)`。因此「凭据泄漏」断言是空转的（对未修复代码同样通过）。改为断言真实可复现的部分 —— **不把请求 URL 回显进 UI** —— 并已验证该测试在旧行为下确实变红。
