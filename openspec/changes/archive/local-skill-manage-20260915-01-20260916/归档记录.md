## 需求摘要

（来自 `proposal.md`）

本地技能页此前只扫描带 `.skillhub/metadata.json` 的目录，**非本仓库来源的技能完全不可见**，且对符号链接没有任何建模，导致更新会摧毁链接关系。本变更要做到：

- **G1 托管所有本地 skill**：扫描 agent skill root 下的全部条目，区分「受管 / 未受管」，未受管项可查看、打开目录、复制路径、**可卸载但强制备份**，但**不提供更新入口**，也不支持「收编为本仓库技能」。
- **G2 安全处理符号链接**：区分 `dir` / `symlink` / `broken-symlink` / `foreign-symlink` 并解析真实路径。**卸载只删链接本身，真实目录原封不动**；**更新写真实目录，链接与目标均保持不变**，使共享同一真实目录的多个 agent 同步生效。以真实路径为单位聚合，一条记录关联多个位置标签，可只解除其中某一个链接。
- **G3 来源跳转**：标题上提供跳转按钮，解析顺序为 `SKILL.md` frontmatter `homepage` > `.skillhub/metadata.json` 中的外挂 `homepage`（安装时写入）> `{registry}/space/{namespace}/{slug}` 兜底；仅允许 `http` / `https`，一律交给系统浏览器。

用户额外追加的要求：软链接在技能名称上加醒目标识。

## 技术方案摘要

（来自 `design.md`）

- **链接语义矩阵（`link.rs`）**：`classify()` 用 `symlink_metadata` 而非 `is_dir()`（后者会跟随链接）。`ForeignSymlink` 是**分类桶而非对文件系统的断言**——它同时容纳「指向文件的链接、链接环、无权限、以及普通文件」，因此任何破坏性分支都必须重新 `symlink_metadata` 判定，不得只看 `kind`。
- **卸载（按位置粒度）**：`Symlink` / `BrokenSymlink` 只 `remove_file` 并返回 `real_path_kept`；`Dir + Managed` 才 `remove_dir_all`；其余一律 `backup_dir` 重命名备份，绝不删除。
- **更新（按技能实体粒度）**：`resolve_install_target` **刻意无副作用**（清理移到下载成功之后，否则一次失败的下载就会先毁掉用户既有条目），返回 `Predecessor ∈ {Absent, Directory, StaleLink, File}`；替换用 `rename(old → aside) → rename(new → dir) → 删除 aside`，失败时把 aside 改回，保证每个中间状态都有内容留在盘上。
- **跟随链接的写入前提**：解析成功后要求目标目录含 `SKILL.md`，否则以 `unsafe_link_target` 拒绝。破坏性动作作用在解析结果上，这是唯一一处「写入目标由文件系统而非本程序决定」的路径。
- **受管判定唯一化**：`has_metadata` = metadata **能被解析**；`detect_status` 返回**不可失败**的 `SkillStatus`（返回 `Result` 会让调用方用 `.ok()` 把解析失败折叠成「此处为空」，进而无备份删除）。
- **`metadata.json` 合并式写回**：读原始 JSON → 覆盖已知字段 → 写回，保留 CLI 写入的 `versionId` / `fingerprint` / `files`。
- **wire 契约**：`InstallInput` 加 `rename_all = "camelCase"`（前端发 `preserveExisting` 而结构体是 `preserve_existing`，serde 静默取默认 `false`，会让「备份并安装」实际执行 `remove_dir_all`）。
- **路径边界**：`ensure_under_roots` 拒绝原始字符串以分隔符或 `/.` 结尾（`Path` 抹掉该差异但内核不抹），只 `canonicalize` 父目录、叶子段按原样保留，按**组件**比较而非字符串前缀。
- 无新增外部依赖（无 YAML crate、无 Tauri 插件）。

- **OpenSpec 对齐评审：CONDITIONAL PASS** — 数字可复现，文档过期
- **TypeScript 评审被中断**，其四项修复改以工具链实证

**一处值得记录的判断**：安全评审建议「要求链接解析出的真实目录也位于某个 agent root 之内」。实测该方案会拦掉本机 79 个 `~/.cc-switch/skills/*` 链接（不在任何 agent profile 中），即用户的主要使用场景，故未采用；改用「链接目标必须含 `SKILL.md`」——实测本机全部 83 个有效链接均满足，而攻击路径 `~/.claude/skills/home -> ~` 因家目录无 `SKILL.md` 被拒。

**诚实说明**：第二轮修复后**未再跑第三轮评审确认**，只有测试证据（见下）。

## 沉淀

本变更向 `docs/architecture/implicit-contracts.md` §10 沉淀了四条约定：

1. `metadata.json` 是 CLI 与桌面端的共享契约，写回必须合并式
2. 「受管」只有一个定义（能被解析）
3. 软链接的两条硬不变量（卸载只删链接、更新写真实目录且跟随前校验目标）
4. Rust ↔ TypeScript 的多词字段必须带 `rename_all = "camelCase"`
5. 前端传入的 `dir` 必须在 Rust 侧对称校验
