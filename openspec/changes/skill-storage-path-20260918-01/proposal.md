# 需求提案：技能存储路径设置（选择目录 / 移动技能 / 恢复默认）

## 背景

设置弹窗（`web/src/shared/components/settings-dialog.tsx`）的「Skill 配置」页目前只有「技能安装方式」一个配置项。该页底部紧跟的「注意」区块（`settings.installMode.noteTitle` / `note`）只是一个纯文本说明，但使用了 `bg-muted/50` 的框式画法，视觉上与上方的安装方式配置项几乎同构，用户很容易把它当作**另一个可切换的配置项**而不是一段注意文案——这是本需求要顺带修掉的第一个问题。

同时，共享安装（`shared`）模式把技能真实文件固定存放在 **`~/.skillhub/skills`**（`repo_root()`，`web/src-tauri/src/installer/agents.rs:83`），该路径是**代码内定的常量**，用户无法更改。对把技能仓库放在其他磁盘 / 目录（外接硬盘、`~/Documents`、工作区）的用户而言，路径不可迁移是一个实际限制；且当前没有任何入口能查看「技能仓库到底在哪」。

## 目标

### G1. 设置页新增「技能存储路径」配置项，与「技能安装方式」视觉分离

- 二者同属「Skill 配置」页，但是**两个独立功能**，需在视觉上明确分开（分组标题 / 分隔线），避免被当作同一个功能的两个子项。
- 语义：展示当前技能仓库真实路径（默认 `~/.skillhub/skills`），提供**选择新目录**与**恢复默认路径**两种操作。
- 仅 Tauri 桌面端可见（与其它技能配置一致），Web 端不渲染。

### G2. 选择新目录：先二次确认，再目录选择，最后迁移并更新软链接

- 形态：**输入框样式**（只读显示当前路径） + 右侧**文件夹/目录图标按钮**。
- 点击图标按钮 → 先弹**二次确认文本对话框**：「修改技能存储路径会把当前路径的技能都移动到修改后的目录，是否要继续？」。
- 用户确认 → 弹出**目录选择框**（复用已安装的 `tauri_plugin_dialog`）。
- 选定目录后 → 把当前路径下**所有技能真实目录**（`~/.skillhub/skills/<slug>` 逐项）移动到选定的目录，并**更新所有指向旧路径的软链接**为指向新路径。

### G3. 支持恢复默认路径

- 提供「恢复默认路径」操作：把技能仓库迁回 `~/.skillhub/skills`，并再次更新所有软链接指向。
- 恢复默认同样需要二次确认（与 G2 的迁移确认一致，避免误触发）。

## 非目标

- **不做**「复制型」（`copy` 模式）已安装技能的迁移——`copy` 的真实文件位于各 agent 目录 `~/.claude/skills/<slug>`，不在仓库根路径下，本次迁移只作用于**共享仓库 `~/.skillhub/skills/<slug>` 下的真实目录及其软链接**。
- **不做**孤儿技能清理 / 垃圾回收（用户主动迁移时不做任何引用检查之外的多余删除）。
- **不做** Web 端的存储路径设置（仅 Tauri 桌面端）。
- **不做** CLI（`cli/`）侧的存储路径设置。CLI 的 `~/.skillhub`（工作区根，`cli/src/platform/paths.ts`）语义保持不变；`repo_root()` 若被迁移，桌面端只改自身读写与软链接，不触碰 CLI 的 `namespace-sync.json`。
- **不做**「一次性把所有 agent 目录里的拷贝型技能也搬进新仓库」的批量迁移——非目标。
- **不做**按 agent 分别设定存储路径（单一全局路径）。

## 利益相关方

- 桌面端（Tauri）技能用户：希望把技能仓库放到自定义磁盘/目录，或恢复默认。
- 本地技能页（`local-skills`）消费者：迁移后 `scan_local_skills` 扫描结果需保持正确。
- 后续 install / attach / uninstall 路径：它们依赖 `repo_root()` / `repo_skill_dir()`，迁移后这些函数必须返回**当前生效路径**。

## 验收标准

1. 设置弹窗「Skill 配置」页中，「技能存储路径」作为一个独立配置分区展示，与「技能安装方式」在视觉上清晰分开；其下方原有「注意」文案不再像配置项。
2. 输入框只读展示当前仓库绝对路径；右侧有目录图标按钮。
3. 点击目录图标按钮会先弹出二次确认文本对话框，文案包含「会把当前路径的技能都移动到修改后的目录」。
4. 确认后弹出目录选择框，可选择一个目录；取消则不产生任何改动。
5. 选定目录后，`~/.skillhub/skills/<slug>` 下所有真实目录被移动到新目录（逐项，目录名 `<slug>` 不变），所有指向旧路径的软链接被更新为指向新路径；迁移后 `list_installed_skills` 扫描结果正确、可正常 install / attach / uninstall。
6. 「恢复默认路径」操作把仓库迁回 `~/.skillhub/skills`，并再次更新所有软链接；同样有二次确认。
7. 迁移/恢复过程中出现单个技能出错时，不得中断整体流程，需以警告形式上报已失败项，其余项继续。

## 已澄清的决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 迁移对象 | 只迁移共享仓库根路径下的真实目录（`repo_root()/<slug>`）及其软链接；`copy` 型（agent 目录内独立副本）不迁移 |
| D2 | 软链接更新范围 | 所有指向旧仓库路径内技能的 agent 软链接（含 `~/.claude`、`~/.codex` 等，按 `local_skills.rs` 扫描出的全部 location） |
| D3 | 新路径持久化 | 路径偏好需客户端持久化，且 Rust 侧 `repo_root()` / `repo_skill_dir()` 需改为读取该偏好（而非常量），保证 install / attach / uninstall 一致 |
| D4 | 确认时机 | 先确认、再选目录：确认弹窗在目录选择框**之前**（用户要求） |
| D5 | 恢复默认 | 「恢复默认」在逻辑上是「迁移到 `~/.skillhub/skills`」，与选择新目录共用同一套迁移逻辑 |
